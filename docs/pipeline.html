Stage-3 Extraction Pipeline

From 100 eligible PDFs to a harmonized table of climate-neutrality pathway datapoints — and a set of cross-study analysis figures. Chained in order by run-stage3.py: PDF → markdown, a first LLM extraction pass, a second pass over the figures the first one could not read, a merge, unit harmonization, then the 05–10 analyses.

# the whole pipeline, markdown → 09
export LLM_ROUTER_API_KEY=<key>
python3 run-stage3.py

›Running it

run-stage3.py chains the steps and stops on the first failure. By default it runs the whole pipeline — markdown → 10, including the 05–10 analysis figures.

# preview the commands, run nothing
python3 run-stage3.py --dry-run
 
# markdown + pass 1 already done, do the rest
python3 run-stage3.py --from candidates
 
# stop after the harmonized tables (skip 05-10)
python3 run-stage3.py --to harmonize
 
# re-run only the 05-10 analyses
python3 run-stage3.py --from sector-balance
 
# just re-merge and re-harmonize
python3 run-stage3.py --only merge,harmonize
 
# locate candidate figures without calling the model
python3 run-stage3.py --only candidates --candidates-dry-run
 
# smoke test on the first 3 papers
python3 run-stage3.py --limit 3

Selection & pass-through flags

  • --from / --to / --only / --skip — choose which steps run (names: markdown extract candidates merge harmonize sector-balance carbon-price mitigation-contribution electricity-price capex macro-economic-cost)
  • --limit N → extract  ·  --model → extract + candidates
  • --candidates-dry-run, --candidates-all, --candidates-papers, --candidates-force → candidates
  • --netzero-fraction, --refresh → harmonize
  • --no-candidates-merge → keep the second pass out of merged-*.csv

Resumability

extract and candidates skip papers that are already done, so a re-run is cheap and an interrupted run continues on its own. If a step exits non-zero the pipeline stops and prints --from <that step> to resume. The API-key steps are checked up front — the run refuses to start if LLM_ROUTER_API_KEY is unset and one of them is selected.

›The two-pass figure extraction

scripts/pdf-to-markdown-extraction.py crops each figure to its own low-resolution PNG region. That is enough for the first pass to read many charts, but stacked bars, multi-panel scenario grids and figures whose axis or legend got sliced off by the crop often come back as candidates rather than rows — roughly 200 flagged figures/tables across ~60 papers.

The candidates step goes back to the source PDF, finds each flagged figure by its caption (handling S… / A.… / B.… / SI / Extended Data labels, and excluding contents pages), renders the whole page at 300 DPI, and re-runs a focused prompt (prompts/stage3c_candidates_prompt.txt) — passing the rows the first pass already got for that figure so they are not duplicated. Structurally un-digitisable items (spatial maps, Sankey diagrams, violin plots) are skipped unless --candidates-all; the model can also return eligible:false to decline a figure it still cannot read.

Preview first: run-stage3.py --only candidates --candidates-dry-run writes outputs/output-stage3c-candidates/<id>/<id>-plan.csv (which figure, which page, match quality) and run_log_dry.csv — no API calls.

›Upstream

Stage 3 starts from the 100 PDFs that reviewers graded eligible after full-text screening. Before that:

  • stage 1 — scripts/stage1-abstract-screening.py: LLM include/exclude on abstracts, compared against the CADIMA reference set.
  • stage 2 — scripts/stage2-fulltext-screening.py: LLM include/exclude on full texts.

Inputs and outputs live on SharePoint (PRE-ReviewClimateNeutrality); inputs/ and outputs/ are git-ignored.
